# 2nd Year — Structure

Second year changed the degree's character. First year taught me to give a computer instructions. Second year taught me to organize chaos — in data, in code, in my own thinking.

Data Structures and Algorithms was the center of gravity. The habit it built: before writing anything, ask what the data wants to be. Who holds it? Is it read more than written? What must it answer quickly? Years later that habit is what fixed slow MongoDB queries in a production dashboard. Almost every performance problem I've met since was a data-structure question in disguise.

Object-Oriented Programming was really about modularity — giving each responsibility a place where it can change independently. I didn't have that vocabulary yet; I had the instinct. When I built MarkNote later, the difference between code I organized and code I merely accumulated was the difference between a project that shipped and one that stalled.

Automata Theory was the strangest course: state machines, grammars, and the provable edges of what computation can do at all. It felt least practical at the time. It grew on me — there is something quietly beautiful about a finite machine recognizing structure in infinite input.

Somewhere in these years I also built Tasky, a small task app in plain vanilla JavaScript, and put it on GitHub. First thing I made for myself instead of a grade.

One lesson carries the whole year: complexity isn't conquered by working harder. It's conquered by choosing the right shape.
